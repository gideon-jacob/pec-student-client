# Contributing to Student Academic Dashboard

Thank you for considering contributing to the Student Academic Dashboard! We're excited to have your help in building a valuable tool for students.

Our goal is to create a student-centric application with a user-friendly UI, helping students manage all their academic details in one place.

## Getting Started

Before you begin, please make sure you have set up the project locally as described in the `README.md`. This will ensure you have all the necessary tools and dependencies installed.

## How to Contribute

We welcome contributions of all sizes, from bug fixes to new features. Here’s how you can help:

### Reporting Bugs
If you encounter a bug, please open an issue on our GitHub repository. In your issue, please include:
*   A clear and descriptive title.
*   Detailed steps to reproduce the bug.
*   What you expected to happen.
*   What actually happened (including any error messages or screenshots if applicable).
*   Your environment details (e.g., browser, operating system).

### Suggesting Enhancements
If you have an idea for a new feature or an enhancement to an existing one, we’d love to hear it! Please open an issue on GitHub to discuss your ideas before starting significant development work. This helps us ensure that your proposed changes align with the project's goals and roadmap.

### Making Changes
1.  **Fork the repository** on GitHub.
2.  **Create a new branch** for your changes (e.g., `feature/your-feature-name` or `fix/bug-description`).
3.  **Make your changes** in your local repository.
4.  **Test your changes** thoroughly.
5.  **Commit your changes** with clear and concise commit messages.
6.  **Push your branch** to your forked repository.
7.  **Open a Pull Request (PR)** to the main repository. Please provide a clear description of your changes in the PR.

## Development Guidelines

To maintain consistency and quality, please adhere to the following guidelines:

### Coding Style
*   Please follow the existing coding style used throughout the project.
*   We use ESLint for code linting. Ensure your contributions pass the linter by running `npm run lint` before submitting a pull request.
*   For TypeScript, try to use specific types where possible and avoid `any` unless strictly necessary.

### User Interface
*   When making UI changes, strive for consistency with the existing design language.
*   Prioritize user-friendliness and accessibility in all UI enhancements.
*   Ensure responsiveness across different screen sizes.

### Commit Messages
*   Write clear, concise, and descriptive commit messages.
*   A good commit message should briefly explain the purpose of the changes. For example: `feat: Add dark mode toggle to profile page` or `fix: Correct calculation error in GPA stats`.

## Questions?

If you have any questions, need clarification, or just want to discuss something related to the project, feel free to reach out by opening an issue on GitHub.

We appreciate your contributions and look forward to collaborating with you!
